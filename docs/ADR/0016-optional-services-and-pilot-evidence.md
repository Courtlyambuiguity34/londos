# ADR 0016: retain PostgreSQL, opt in to public copies, distinguish demonstrations from research

Status: accepted for the local implementation on 2026-10-07; external release/pilot approvals remain open.

The owner selected a computer-hosted first installation, Brevo email, possible Render free web service and optional MongoDB/Redis/Cloudinary. The owner explicitly corrected the database request: retain the current PostgreSQL database and do not run a migration. Canonical rent, native auth/MFA, scopes, jobs, privacy and recovery already depend on PostgreSQL transactions/constraints and cannot be replaced by a connection flag.

PostgreSQL remains canonical. Manual MongoDB commands implement a bounded public catalogue copy with Cloudinary links for normalized managed public images. No identities, private evidence, enquiries, finance or audit data is copied. Redis has an explicit connection check; existing caches/queues retain their semantics. All optional services default off, and a canonical migration flag or unsupported engine fails closed. Copies can be stale and need external retention/removal governance; they are not live rendering or failover. A future canonical backend requires a separately verified design and migration.

Brevo reuses existing notification job identities and schemas. An additive delivery receipt stores only payload fingerprint, attempt/outcome/time and provider reference. Exactly one durable network attempt is admitted for a job with a current lease and unchanged payload. Accepted attempts deduplicate acknowledgement-loss retries; unknown outcomes never blindly resend, even after operator replay. This avoids depending on a provider's finite deduplication window, at the cost of possible nondelivery after a pre-transmission crash. Reconciliation and a separately regenerated action are required. Local adapters still never send externally.

The owner requested seeded users, not fictional business conclusions. Twelve clearly labelled native demonstration accounts have no privileged grants, public publication or manufactured financial credits. A fresh-MFA operations page retires only registered demo identities, revokes sign-in/sessions/staff access, archives shops and preserves the legal owner record and immutable history. It does not pretend to perform real subject-access/account erasure. Applied 001–018 are frozen; 019 is expand-only and old readers remain compatible in the verified local rollback scope.

P13 uses a closed pseudonymous input journal, a plan hash, explicit preregistration/policy references, predeclared numeric proposals and exact integer economic calculations. First actual renewal, waiver-supported coverage, stated intent, actual costs and missing sources remain separate. Demonstrations/incomplete evidence cannot generate go. Hashes and supplied references support review but cannot prove external facts. G5 verifies current source/configuration and bounded live review receipts; it opens no service and does not convert local rehearsal into production approval.

The consequence is a useful local build and honest release/research tooling without an implicit database migration or provider purchase. Real keys, verified sender/inbox, hostname/ingress, independent recovery/key/privacy authority, named responders, production lifecycle/rights/policies, field accessibility, launch and real cohort outcomes remain concrete gate conditions.
