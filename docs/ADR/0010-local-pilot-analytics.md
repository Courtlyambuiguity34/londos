# ADR-0010: local privacy-minimized pilot analytics

P9.5–P9.7 development packet, 2026-10-05. Preserve all completed business/security workflows. Live analytics is disabled; an explicit loopback/database-mode flag enables fictional development capture. No external analytics provider is introduced.

The eleven pilot events are mall visit, search submitted, search results viewed, shop result clicked, shop viewed, department viewed, product viewed, contact action clicked, direct link entry, merchant publish and merchant catalogue update. Public events use short-lived signed rendered-page contexts, strict allowlisted fields and current canonical public eligibility. A context permits only its page actions and rendered shop targets. No query text/hash, URL/referrer, IP, user agent, email, visitor cookie, account ID, contact values or private evidence is stored. Bot/internal, DNT and GPC traffic is filtered where practical; this is bounded filtering, not fraud-proof measurement.

Anonymous retry identity is a rendered-page context, expires after 30 minutes and is not a visitor identity. Receipt hashes expire with their contexts; hashed minute-budget keys use the existing two-hour maintenance window and never identify a visitor; retries count each event/target/contact channel once per rendered page. Concurrent receipt and aggregate writes commit atomically. Only daily event/source/detail counts and current canonical shop/merchant foreign keys persist. Search quality records only zero/few/many result buckets. Counters measure observations, not unique people, orders or sales.

Direct/discovery attribution is an observed browser navigation source, not verified causal attribution. A bounded per-tab session-storage record retains at most ten shop/source entries for 30 minutes, no visitor ID or raw URL/query, and a two-minute pending clicked-shop marker. Matching mall/global search result navigation is discovery; fresh external/empty-referrer entry is direct; otherwise source is unattributed. Existing same-shop attribution survives department/product navigation and reloads until expiry. Blocked or unwritable navigation storage records unattributed page observations, never an invented direct entry. Private preview never emits public events. Contact navigation proceeds without waiting for capture; disabled/failed analytics never blocks storefront rendering, contact, publication or catalogue mutation.

Merchant publish and catalogue update counts derive from existing committed append-only audit records joined to tenant-consistent canonical resources. Failed/conflicting canonical commands cannot produce these events, and analytics storage is not part of their transactions. Historic audit counts are explicitly distinct from captured browser observations. No historical browser events are invented.

The capture endpoint uses exact origin, bounded JSON, signed context expiry, known-bot/privacy/internal filters, global/context budgets and a small separate database pool with short query/lock/connect limits. Its generic receipt reveals no eligibility, target existence, dedupe or storage result. Capture is lossy under outages/limits, with no durable browser retry backlog. Counts cannot certify traffic authenticity or paid conversion.

Owner-only shop aggregate reads require current fresh ownership before HTML/Flight and again after merchant serialization. Explicit global operator analytics permission and native fresh MFA permit bounded platform aggregates, activation/time-to-first-publish, renewal payment/waiver distinction and case backlog summaries. They grant no private case/evidence/contact/history/ledger access or decisions. No raw analytics receipt/event viewer or arbitrary tenant selector is provided. Default seed grants stay unchanged; guarded local setup can grant analytics only to the verified fictional operator without changing credentials.

Invalid retention settings disable capture and aggregate deletion; they never silently delete history using a fallback policy. Development aggregate retention is configurable from 7 to 90 UTC calendar days, default 30, including today. Reads exclude expired data immediately. Existing fenced maintenance deletes expired receipts and aggregate rows in bounded batches; a stopped worker leaves physical cleanup pending, which is not claimed complete. This covers these minimal analytics tables only: broader verification/enquiry/incident/legal/backups export/deletion/retention remains P9.8. No applied business/audit history is deleted.

Acceptance requires additive schema-013 upgrade preservation, all eleven event semantics, atomic concurrent dedupe, signed/expired/foreign context denial, current eligibility/resource ownership, internal/bot/privacy filtering, bounded retention and no private raw data storage, real revoked ownership/grant/freshness checks, analytics outage containment and native accessible browser journeys. P9.9 costs, live privacy/legal policy, sustained load and production release remain separate gates.
