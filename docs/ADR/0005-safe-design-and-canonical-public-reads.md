# ADR-0005: safe design revisions and canonical public reads

Accepted for the local X2 prototype on 2026-10-05. This extends [ADR-0004](0004-catalogue-contact-and-private-media.md); it is not production release approval.

LSS schema 1 is the first executable interpretation of the illustrative specification. Its closed registry contains version-1 department shelves, explicit product shelves, plain-text stories and contacts. Themes are fixed accessible earth/plum/blue presets. Eight unique spaces, 32 product cards, eight cards per source, three unique contact actions and a 7,000-byte specification budget bound complexity. Script/HTML/CSS/URL properties, trusted badges, arbitrary SEO/extensions and unknown versions/props are rejected. Text containing markup is rendered as plain text through React escaping. Canonical platform navigation/status/report disclosures cannot be removed by a design. The broader component registry remains a full-build obligation.

Drafts and published pointers are separate from immutable, tenant-consistent revisions. Design saves, constrained patches and restoration use current design/shop grants and compare a base version after the merchant lock. Restoration appends a draft; publication requires explicit confirmation, a matching saved revision, separate publish permission, recent native authentication and current tenancy/moderation eligibility. Every command is audited in the same transaction. A draft never becomes public because it exists. Catalogue, prices, contact/payment instructions and financial state are not copied into LSS. Missing references are omitted or show shop-level fallbacks; unsupported stored legacy layouts use a small platform fallback instead of executing their props. Invalid new publications are rejected.

The initial public `SearchService` uses PostgreSQL-generated English search vectors and partial GIN indexes over canonical shop/department/product data. One best match per shop prevents inventory volume from directly multiplying exposure. Department/name relevance, deterministic ties, scope-bound validated cursors, 20-row pages, eight words/80 characters and a two-second statement timeout bound requests. Empty-query browsing includes recent eligible publications. Categories and shop-local scope are supported; advanced typo correction, multilingual relevance, promotion and live spam/moderation operations remain later work. Internal mall assignment and rent never enter organic ranking.

Public visibility is one shared rule: active publication, active/due/grace tenancy and clear moderation; discovery/rendered shops additionally require a published design pointer. Due/grace never independently overrides moderation. The P5 opted-in contact page keeps its separate minimal contact contract. Ready public image reads also recheck current eligibility, attachment to an unarchived product/department and ready state; raw quarantine/rebuild-source variants remain inaccessible. Images use fixed processed variants with responsive selection, explicit dimensions, alt text and lazy loading. Immutable shop UUIDs and product/department UUIDs redirect only after current authorization/eligibility to their current safe slugs.

There is no shared application/CDN response cache in this prototype. Dynamic routes, no-store headers, disabled public prefetch and request-local React memoization provide current reads without broad invalidations or eventual index jobs. Generated vectors update in the canonical transaction and rebuild with PostgreSQL indexes. This deliberately replaces the originally proposed asynchronous public projection for the initial workload; internal profile projections are not a disclosure source. Read-only repeatable-read transactions make a shop response internally consistent. Visibility is checked for each new request; content already delivered to a browser cannot be retroactively erased. Remote CDN/router/persistent browser-cache revocation still needs deployment-specific evidence before release.

`LONDOS_DATA_SOURCE=database` explicitly selects this configured local core. `fixtures` remains supported and separately tested. Public remote operation, object storage/CDN, real payments/providers, approved privacy/retention rules, live report delivery and backup recovery remain blocked by their own gates. Migration 009 is additive/checksummed; its new revision-size check applies to new writes without rejecting pre-existing legacy rows.

## Predeclared architecture experiment

The guarded benchmark creates and removes its own random local test database, generates 1,500 synthetic shops/~150,000 products, adds only marked synthetic design fixtures, and runs the compiled web/worker. It never modifies the existing development volume. Before measurement, the local prototype targets are:

- Indexed search service p95 ≤250 ms; warm SSR+body p95 ≤500 ms on loopback.
- A fixed 20-client/200-request mixed loopback burst: no HTTP failures and p95 ≤1,500 ms.
- Estimated gzip HTML ≤80 KiB; observed initial encoded JavaScript ≤200 KiB and image resources ≤350 KiB.
- A supported 6,000×2,000 phone-sized image: upload command ≤1,000 ms, durable worker ready within 5,000 ms, processed dimensions within the declared variant bounds.

These are experiment limits, not a capacity, mobile-network, photographic-quality, production SLA or recovery guarantee. Record query plans, service query counts, timings, RSS/CPU observations, cgroup limits, worker lag and measured freshness. A failure requires investigation and an honest report; do not quietly relax a budget after observing it. The six-slice gate is the prototype boundary; P8–P12 and the wider component registry remain open.
