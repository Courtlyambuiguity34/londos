- Retained the existing MongoDB driver, public-copy adapter, Cloudinary adapter and durable Brevo delivery. PostgreSQL remains authoritative; migrations 001–019 are byte-identical and no migration was performed.
- Added preferred `MONGODB_URL` support with backward-compatible `MONGODB_URI`. Conflicting aliases, missing/invalid database selection, malformed input and insecure TLS flags fail with generic errors. Atlas URIs without a database require explicit `MONGODB_DATABASE`; settings cannot silently select a system/default database.
- Remote clients enforce TLS and certificate/hostname checks. Explicit driver log suppression prevents environment-enabled debug output from bypassing sanitized reports. Tests initially caught the driver's mapping of TLS-bypass options to `rejectUnauthorized`/`checkServerIdentity`; the check and client options were corrected before the passing rerun.

No database/collection is dropped and unrelated documents are preserved. Failure reports never expose raw driver errors.
- Linked public products to Cloudinary image metadata through `imageAssetId`/`assetId` and merchant alternative text. Content-addressed public IDs locate copies. Delivery URLs must identify the exact expected asset in the correct cloud; publication eligibility is rechecked. The application still renders its existing PostgreSQL media path.
- Added `/landlord/services`, restricted to operations permission and recent native MFA, showing fixed configuration warnings/status without secrets or provider requests.
- Bounded Brevo read-only verification responses during streaming and added mock account/sender checks. Durable accepted/uncertain/rejected delivery behavior remains protected by its existing integration regressions. No live email was sent.
- Split the existing Redis integration test into its own file so this targeted MongoDB campaign does not provision Redis. Absent `REDIS_URL` does not block local startup, tenancy, subscriptions or durable jobs.
