## Implemented boundary

- Closed provider-neutral `AIProvider`, fixed HTTPS Gemini/OpenAI adapters and `LondosDesignOrchestrator`. Gemini is initial when configured. Logical design roles share one constrained intent contract, without tools or separate mandatory role calls.
- Exact supported theme/action/uniquely named department moves require **zero provider calls**, including explicit quality-review requests. Other instructions need merchant consent and configured remote processing. Gemini slot 1–5 selection supports the requested pool; optional single authentication-only spare and explicit OpenAI outage fallback never cycle credentials/providers on quota or cooldown.
- Fresh current design access precedes context assembly and follows network/database waits. Minimal public shop labels, bounded active owned catalogue IDs/names/versions and current LSS exclude private contacts, descriptions, evidence, members and credentials. Provider strings are untrusted data. No unrestricted database/filesystem access, tool execution, arbitrary generated code or external URL selection exists.
- Structured patches include existing theme/actions/move plus bounded announcement and add/replace/remove of existing safe space types. Complete LSS schema/page/card/identity limits and canonical owned references run before proposal storage, preview, draft application and separate publication. Unknown operations, malformed/oversized output, foreign IDs and script-like generated text fail closed. SQL/JS strings have no execution path and remain literal escaped text if otherwise allowed.
- At most three attempts: one bounded repair or transient retry, then selective OpenAI review for explicit quality, low confidence, recommended review or successful repair. Reviewer output passes the same validator; invalid review never becomes an accepted candidate. Changed/low-confidence/unavailable review is visible and requires explicit acknowledgment when a candidate is offered.
- Request/context/provider-response limits are 2,000 characters / 32,000 bytes / 65,536 bytes; output text is at most 8,192 bytes and capped at 2,048 tokens. Provider timeout is eight seconds, overall request deadline 30 seconds, durable lease 40 seconds and candidate expiry 15 minutes. Wire payload size is bounded, response streaming/redirects are guarded, abort fences late ignored responses and shared durable `Retry-After` cooldowns stop future calls.
- Durable admission serializes one active request per shop / three globally, 20 requests per shop per UTC day, one million conservatively reserved tokens/day, and a configurable USD-estimate budget (default 1,000,000 micro units). Each remote request reserves all three permitted calls at the highest configured provider estimate; failures/missing usage retain reservations for the day. A reservation or recorded estimate is not a provider bill, refund promise or merchant charge.
- Immutable original-actor retry identity avoids repeated calls on concurrent/lost-response retries; changed payloads conflict. Original requester plus current fresh design authority, exact proposal version, unchanged base/context/resource versions and confirmation guard application. New draft, scrubbed terminal result and minimal audit commit atomically, with real SQL failure rollback. Another designer cannot inherit a request by guessing its ID. Operator cost/support scopes confer no design authority.
- No raw instruction/prompt, invalid response or provider error body is retained in database/audit/logs. Only the validated candidate/patches remain until apply/reject/cancel/expiry. Terminal receipts and redacted provider/model/fixture-or-live-transport/purpose/outcome/latency/reported-token/configured-estimate metadata persist. Existing lease-fenced maintenance scrubs up to 1,000 expired/dead-lease candidates; read/apply expiry is immediate even if maintenance stops. Production metadata retention and physical backup obligations remain open.
- Assistant and existing owner/operator costs show bounded provider aggregates separately from UGX work, with fixture labels and missing usage explicitly unmeasured. Existing private headers, origin/CSRF checks, native authentication and authority rechecks remain active. Public canonical rendering contains no provider path and performs zero calls.
