## Implemented behavior

Anonymous customers submit bounded fictional concerns without an account. Exact origin and atomic loopback budgets protect intake; identical UUID-key retries create one immutable report/case, while changed payload/capability conflicts. Known and unknown targets receive a generic receipt without private target/case metadata. Reports never automatically hide a shop. One image up to 2 MiB can be attached within 30 minutes before any case claim; secure decoding strips metadata and stores normalized WebP only. The private capability stays in browser memory/request, is hashed at rest and never appears in a URL/receipt/operator response. Private report/image has no anonymous or merchant download.

Native-MFA reviewers need explicit moderation permission and a distinct claimed trust-case scope. Active merchant self-membership denies review. Minimal 20-row queues expose category/state/age/priority, with pending appeals first, then priority and age; private report text/image remains scoped. Notes/priority changes retain private history without changing moderation. Confirmed decisions compare case and moderation versions, recheck current authority after the merchant lock, and commit case, canonical moderation, shop version, immutable events/audit and private owner jobs together. Private reasons and merchant-facing explanations are separate.

Strongest case restriction wins alongside an immutable captured legacy baseline. Dismissing/reinstating one case cannot clear another or a pre-existing restriction. Conflicting external moderation changes fail closed. Fresh owners see redacted own-shop decisions and submit versioned appeals; a different reviewer must clear the last reviewer’s restriction. Restoration changes no rent/ledger, publication pointer or operational hold. All current public consumers remain canonically gated. Guest enquiry submission now uses the same shared eligibility as rendering, closing an existing gap where a paused shop could still accept a direct request.

Approved P8 application review, provisioned shop identity and private reviewed evidence derive a platform-controlled **“Development application reviewed”** disclosure. It explicitly describes fictional local review and gives no identity, product or payment guarantee. Unreviewed shops show no badge. No applicant fields/evidence are exposed and merchant profile/LSS cannot supply the status.

Ordinary seed privileges remain unchanged. Explicit guarded `npm run db:trust` grants the verified fictional operator and creates/preserves a separate fictional independent reviewer with moderation permission only and no merchant memberships. Random credentials stay in ignored mode-600 `.local/trust-reviewer.json`; mismatched existing identities/files refuse reset. Native MFA and separate claims still apply. Repeat setup preserved configuration and both private account files; no credentials were printed. This was run on the main local database after migration.

Initial cleanup forcibly dropped its isolated PostgreSQL database before idle connections drained, producing an unhandled termination after otherwise passing cases. The P9 fixture now closes its pool, waits for its owned database connections to drain, and performs a guarded normal drop without suppressing errors. A clean full integration rerun passed all 120 tests.

Initial browser selectors confused a form’s accessible name with its textbox and Next’s route announcer with the expected application alert. Exact textbox and main-scoped alert selectors retain the intended assertions. A later full run passed every new P9 test but exposed an existing design timing race: previous “Draft saved” feedback remained visible while a subsequent patch was still saving, allowing navigation to the previous revision. The workspace now announces the in-flight action and disables preview until refreshed saved state is available, with prefetch disabled for private preview. The existing [design journey](../../tests/e2e-core/x2.spec.ts) deliberately holds the patch request, asserts preview unavailable, releases it, and verifies the revision-2 link and rendered revision. No private-preview authorization or revision assertion was weakened.

One verification command omitted this cloud environment’s system Chromium override and failed before executing browser tests; the documented override corrected it. The final full core browser run passed all **21 tests**. All failures above were retained as diagnostic information; they are not counted as successful runs. No GitHub Actions execution, new sustained-load experiment or production recovery is claimed.
