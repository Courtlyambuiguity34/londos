## Delivered

Six original themes—**Atelier, Terrain, Harvest, Signal, Studio and Pulse**—use
separate reviewed JSON definitions and automatic registry generation. They have
distinct entrance, typography, collection and card compositions. A visual picker
applies theme choices to an unsaved draft while retaining merchant copy,
branding, catalogue references and contact actions. Named theme commands also
compile locally in the existing design assistant, without a provider call.

The storefront has image-led entrances, usable collection tiles, readable
product cards and dedicated department/product layouts. Exact repeated sections
render once without rewriting saved history. New narrative sections start empty;
explicit cleanup and section edit/reorder controls let the merchant fix a draft.
Narrative-only published designs can show their bounded current owned catalogue.

The catalogue, designer and landlord communications screens have focused panels,
paired desktop fields, single-column phone layouts, keyboard tab navigation and
retained input between panels. Panel selection survives publication/RSC refresh.
The publication confirmation, current version, freshness, grants, private
previews and immutable revision history remain authoritative. No decorative
analytics, orders, testimonials, merchant products or commerce claims are invented.

Read the [merchant/workflow guide](../STOREFRONT-THEMES.md) and
[theme extension guide](../../src/modules/shop-themes/README.md).

## Issues found and resolved during verification

- Sandbox subprocess blocks and cancelled permission requests were not test
  passes. Verification resumed with the required execution permission.
- The theme registry needed JSON import attributes for direct Node/Playwright
  ESM consumers; generation now emits them and respects repository formatting.
- A full-image hero overlay could intercept department product links. Compact
  department headers no longer acquire that full-image state; all six themes’
  department/product links passed after the correction.
- Explicit accessible section-text labels fix exact textarea targeting and keep
  controlled text editable, including temporarily empty unsaved input.
- The shared panel hook remembers only a bounded panel ID per pathname in memory,
  so a publication refresh cannot send the user away from Review. No form values,
  authentication state or permissions are stored in that cache.
- A failed image inside a collection link no longer nests a retry button in the
  link. The collection remains navigable; standalone images retain Retry image.
- Same-name browser fixtures now deliberately choose distinct readable addresses,
  respecting the production reservation rule rather than weakening it.
- Browser assertions now use the panels’ actual accessible heading names and wait
  for streamed metadata before checking document-title accessibility.
- The communications screen has a single main heading after removal of its
  redundant inner title. Earlier completed evidence and source work were preserved.

## Deployment and remaining limits

Redeploy the updated hosted branch with the existing configuration. No new
packages, credentials, environment settings or SQL migrations are required.
Readiness remains migration036; PostgreSQL, optional MongoDB/Cloudinary/Redis,
Brevo limits, rent/finance data and existing readable shop URLs remain unchanged.
Existing shops are not automatically published or assigned a new named theme.

Choose a theme in Design & publish, save, preview and explicitly publish it.
The common renderer improvements apply to existing designs; stored copy and
revisions remain intact. The specific live merchant shop was not modified.
Production rollout, live credential/provider health, real-device review and the
later comprehensive verification remain separate. Existing formal release/pilot
conditions are not relabelled complete by this frontend work.
