# Public browsing rails and shop purchase card

Checked 27 October 2026, continuing from `3fd5ef4` on
`feature/hosted-lifecycle-secure-2026-10-23`.

## What changed

The purchase information beneath each shop is a single, responsive card with an
icon, clear heading, readable copy and a separate report link. It uses the shop's
surface and text colours, including Nocturne, instead of a white rectangle on a
dark page. The existing payment/merchant disclosures and report destination are
preserved. A private preview still omits the public report link. Fictional sample
pages retain their sample-only information.

The mall and search category bars, and canonical/sample shop department bars,
share the same browsing component:

- When the contents overflow, the bar moves at a steady 24 CSS pixels/second and
  repeats continuously across the boundary. It shows every item rather than
  hiding later departments. If everything fits, it stays still.
- Pause/resume is explicit. Hover and keyboard focus stop movement. Touch and
  wheel input retain native scrolling and pause automatic movement for six
  seconds after interaction. Offscreen bars and hidden tabs stop animating.
- Reduced-motion preferences disable automatic movement. Links remain manually
  scrollable. Without JavaScript, one normal, horizontally scrollable set of
  links works as before.
- The repeated visual links remain clickable, retain the same destinations and
  search filters, and do not duplicate keyboard or screen-reader navigation.
- Public and private-preview destinations still come from their existing server
  helpers. Authentication, revision/proposal identity and media access are not
  relaxed. Private workspaces and form tabs do not auto-scroll.

## Verification

The initial baseline passed 19 storefront/theme unit tests and two production
browser checks covering public discovery and all ten themes. The production build
and production launcher also completed successfully after the changes.

Final results: **19 unit tests** and **39 distinct browser scenarios** passed
(23 hosted-core scenarios, including all ten themes and the designer/private
catalogue workflows, plus 16 desktop/phone sample-site scenarios). TypeScript,
changed-file ESLint, formatting, documentation links, whitespace and the
configured-value artifact scan also passed. The artifact scan checks exact
configured values only and does not replace general secret scanning.

Focused browser checks cover the loop boundary, pause/resume, hover, keyboard
focus, a native phone swipe, wheel scrolling, repeat-link clicks, retained search
refinements, fitting desktop layouts, reduced motion, and JavaScript-free
navigation. All ten themes are checked at 1440px and 390px, including the purchase
card and report link. The studio and public discovery checks also exercise 320px.
Configured WCAG A/AA axe checks and horizontal-overflow checks pass; this is not a
full accessibility certification.

An additional private-preview regression exposed an older selector assumption:
`Fictional private preview image` was expected to identify one element, while
the existing renderer uses it in a cover, collection tile and product card. The
same strict-selector failure was reproduced on untouched commit `3fd5ef4` in a
separate temporary checkout. The test now checks every rendered image, including
lazy loading, owned private URLs, WebP bytes and private caching. Anonymous,
foreign-account, source-image and unpublished-public-access assertions remain.
The wider catalogue run also found an old exact shop-link label in the product
search test. Product-match links already announce the product and shop together.
That failure was also reproduced on untouched `3fd5ef4`; the test now locates the
exact product-and-shop label while retaining archive, restore and unpublish checks.
