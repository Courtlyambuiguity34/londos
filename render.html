Londos setup reference

Run locally, then prepare Render.

Review checklist — no deployment or live provider verification is performed by this page.

Supported storage

PostgreSQL holds accounts, tenancy, rent/subscriptions, jobs, audit and canonical catalogue/media ownership. MongoDB optionally holds public catalogue copies; Cloudinary holds normalized public image copies. Redis is optional and may remain absent.

Render still requires reachable PostgreSQL and an independent supervised worker. A MongoDB-only deployment is not supported by this implementation.

First local installation

  1. Use Linux/Ubuntu or WSL2, Node 24.19.0, npm 11.9.0 and Docker.
  2. On the implementation branch, run npm ci --no-fund, then npm run db:local.
  3. Edit the ignored .env.local privately: choose database mode, a loopback origin and local adapters. Keep generated secrets and PostgreSQL authority.
  4. Run db:migrate, db:seed, db:operations and build through npm.
  5. Run npm run start -- --port 3000 and, in another terminal, npm run worker.
  6. Confirm database/authentication and a ready worker at /api/ready. Read private fictional credentials locally; enroll native MFA for operator access.

Render preparation

  1. Review the exact branch/commit and open launch obligations. Back up before migrations; use separate migrator and least-privilege runtime roles.
  2. Review the free Docker web blueprint with auto-deploy off. Use deploy/Dockerfile, repository root context and /api/ready.
  3. Supply reachable PostgreSQL, a private stable auth secret, the exact HTTPS auth origin and real verified Brevo settings in Render's environment facility.
  4. Provide an independently supervised worker using the same compatible artifact and database. Free web sleeping/ephemeral storage is not durable worker or backup infrastructure.
  5. For optional copies, privately supply MONGODB_URL, an explicit copy database and CLOUDINARY_URL; enable their flags manually. Keep migration false and Redis disabled.
  6. Verify trusted ingress/client IP, TLS, backups/privacy authority/key recovery, responders and live policies before public release.

Provider checks and warnings

Run npm run mongo:verify on a protected tooling host for temporary CRUD and cleanup, npm run email:verify for read-only Brevo account/sender validation, and npm run services -- check for enabled optional services. Keep keys and connection strings out of command arguments, screenshots, documentation and Git.

The operations page /landlord/services requires recent native MFA and shows fixed configuration warnings. A configured status is not a successful network test. Mock tests do not prove live provider credentials or inbox delivery.
